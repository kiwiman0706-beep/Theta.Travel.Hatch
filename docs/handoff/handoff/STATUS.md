# 現在の実装状況と制約

## あるもの

- `requirements/travel-app-concept-v0.1.md`: 初回構想から地図・公共交通・持ち物の追加まで反映した文書。
- `mockup/tabi-no-tane-portable.html`: 単一HTMLファイルの操作可能な画面試作。ホーム、スポット、しおり、思い出の四画面。ブラウザーで開ける。
- `mockup/source/travel-mockup-fragment.html`: 同じ試作の画面本体。HTML/CSS/JavaScriptを編集する起点。
- `mockup/archive/tabi-no-tane-original-snapshot.html`: 前スレッドで渡した保存版。原本保全用。

試作で操作できる内容: 条件チップによるサンプル提案、スポット追加と状態別地図、しおりの日程切替、車/公共交通の切替と往復の乗換メモ編集、持ち物の追加とチェック、訪問履歴の一覧/表/地図表示。

## まだないもの

- Android Studio/Gradleのプロジェクト、APK、署名鍵。
- Gemini API、実際の地図・ジオコーディング、天気、施設、経路、時刻表との接続。
- 端末への永続保存、同期、バックアップ、実写真の取り込み、音声入力。
- 実データを使った旅程生成や空室・営業・運賃の確認。

## 試作を使う際の注意

画面内の白浜・奈良・大阪などの場所、時刻、天候、地図ピンはデザイン確認用のサンプルです。スポットを追加してもページを閉じると消えます。地図は地理的な正確さを検証するものではありません。「しおりを保存」はモック上の表示で、実際の永続化ではありません。

## 引き継ぎ時に確認する設計判断

- 主な出発地・交通手段の初期値。モックの「大阪発・家族」はサンプルであり、固定要件ではない。
- 端末間の同期とPC表示を初期版に入れるか、後続版にするか。
- 初期の履歴取り込みを手入力から始めるか、写真などからの候補抽出も入れるか。

これらが未確定でも、データの基本設計とオフラインの保存部分から実装できます。
