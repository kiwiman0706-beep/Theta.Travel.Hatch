# 旅行計画・おでかけ記録アプリ 構想 v0.1

作成日: 2026-09-29

## 目的

「行ってみたい」を気軽に貯め、時間・天気・同行者などから現実的な行き先を選び、計画と実際の思い出を一続きで管理する Android アプリ。旅行のしおりと、おでかけ先の個人データベースを兼ねる。

## 基本の流れ

1. **行きたいを追加**: 「アドベンチャーワールドに行きたい」と入力・音声入力。施設の URL や共有メニューからも保存する。AI が候補地、場所、特徴、子連れの注意点、屋内外、所要時間などを整理し、ユーザーが確認して保存する。
2. **条件から探す**: 「今日は雨」「午後から」「今から1泊」「車で2時間以内」などを指定。保存済み候補と過去の訪問先を絞り、現在の天気、営業、移動時間を確認して候補を提案する。登録した全スポットを一枚の地図にもプロットし、「全部／行きたい／行った」で切り替える。
3. **旅程を作る**: 出発地、日時、交通手段、人数、予算をもとに、時刻ごとの行程、予備案、持ち物、予約リンクを含む編集可能なしおりを作る。公共交通の場合は往路・復路ごとに出発駅、乗換駅、路線・便、時刻、乗換余裕、切符メモを保存する。持ち物は旅程ごとのチェックリストにする。確定していない料金・空室・休業は「要確認」と明示する。
4. **行った記録にする**: 計画からワンタップで訪問記録を作り、実際の日付、訪問先、写真、感想、費用、雨でも楽しめたかなどを残す。計画しなかった外出も直接登録できる。
5. **あとで見返す**: 年表、一覧表、地図で表示。地域、日付、天候、屋内外、同行者、子どもの年齢、満足度、再訪希望などで検索する。

## 画面案

| 画面 | 主な内容 |
| --- | --- |
| ホーム | 大きな「今からどこ行く？」入力欄、今日の条件、続きの計画、最近の記録 |
| スポット | 行きたい場所と訪問済みを同じ地図にプロット。状態別フィルターと一覧表示。URL・音声・手入力からすぐ追加 |
| 予定 | 日帰り・宿泊のしおり。行程、移動と乗換、持ち物の3画面で時刻、予約、雨天時の代替案を編集 |
| 行った | 訪問履歴を時系列・表・地図で切替。写真と感想を表示 |
| 共通の検索 | 自然文と条件チップを併用。「雨の日に楽しかった場所」も検索 |

「＋」は各画面に常設し、行きたい場所、計画、訪問記録のいずれにも直接追加できる。

## 「今から1泊、白浜へ」の動作例

入力: 「今から1泊でアドベンチャーワールドへ。子ども連れ。明日は雨かもしれない」

アプリは出発地・出発できる時刻・交通手段を保存済み設定から補い、不足する条件だけ尋ねる。天気と移動時間を取得し、目的地の営業情報を確認する。Gemini が移動と食事、休憩を含む2日間の案と雨天案を組み立てる。宿泊候補や予約サイトを示すが、空室や金額は実際に確認できた時点の情報として扱い、予約確定とは表示しない。保存した計画は旅のあとに訪問記録へ引き継ぐ。

## データの単位

| 単位 | 保持するもの | 関係 |
| --- | --- | --- |
| 場所 | 名称、座標、地図 ID、URL、屋内外、対象年齢、タグ、メモ | 同じ場所を複数の旅程と訪問に使える |
| 旅程 | 日付、出発地、同行者、条件、行程、予約メモ、変更履歴 | 複数の場所を時刻順に含む |
| 訪問 | 実際の日付、行った場所、写真、天候、感想、費用、再訪希望 | 旅程なしでも作成可能。同じ場所に何度でも訪問可能 |
| 移動区間 | 往路・復路、交通手段、駅・停留所、路線・便、出発・到着時刻、乗換、切符・予約メモ | 旅程に複数登録できる。手入力した内容と取得時刻付きの検索結果を区別する |
| 持ち物 | 品名、カテゴリ、必要数、担当者、チェック状態 | 旅程ごとに保存。定番品は次回の旅へ複製できる |

場所は「行きたい」「行った」の二択に固定しない。再訪したい場所、何度も行った場所を自然に扱う。AI が付けたタグは編集でき、入力元と確認日時を保持する。

## 推薦の考え方

まず天候、出発時刻、残り時間、移動上限、営業予定、予算、同行者の条件で候補を絞る。次に移動負担、子どもとの相性、屋内外、過去の満足度、再訪希望、新規性を使って並べる。候補ごとに「雨でも遊べる」「15時出発で間に合う見込み」など理由を表示する。ユーザーは「新しい場所を優先／また行きたい場所を優先」を切り替えられる。情報が足りない場合は理由付きの「要確認」を残す。

## 技術方針

- Android の APK。まず端末内に場所・旅程・訪問データを保存し、通信がなくても閲覧・編集できるようにする。地図や現在情報の取得には通信が必要。
- Gemini API は自由文の読み取り、候補の要約、条件に沿う行程案、自然文検索の補助に使う。AI の出力は下書きとして扱い、保存前に編集できるようにする。
- 場所の特定と営業時間には Google Places、地図表示には Maps、移動時間には Routes などの構造化データを検討する。営業時間や休業は訪問直前に再確認する。
- すべてのスポットには座標を持たせる。名称だけでは場所を特定できないときは候補を選んでもらい、誤った位置へピンを置かない。地図のピンは行きたい／訪問済み／両方を区別し、近いピンは件数表示でまとめて拡大時に展開する。同一地点の複数訪問は一つのスポットから履歴を開く。
- 公共交通の乗換情報は初期版で手入力・編集・保存を実装する。経路検索や時刻表との連携は後から追加し、取得時刻と再確認表示を付ける。持ち物は旅程から独立したチェック項目として保存する。
- 天気は予報 API から地点・時間別に取得する。予報の取得日時を示し、雨天案を併記する。
- 訪問履歴は CSV/JSON として書き出せるようにし、写真は別途まとめてエクスポートできる設計にする。バックアップや PC 表示、家族共有は後続段階で検討する。
- API キーはソースや APK に固定しない。試作時に端末の設定画面へ入力する方式は可能だが、配布や本格運用ではサーバー側で Gemini キーを管理する構成にする。

## 段階的な制作

**第1段階: 使える試作 APK**

- 行きたい場所の登録、編集、削除、URL 取り込み、Gemini の要約
- 日帰り／1泊のしおり生成と手動編集
- 計画から訪問記録への変換、計画外の外出の記録
- 当日の天気と入力した残り時間に応じた候補の提案
- 登録済み全スポットの地図プロット、状態別フィルター、訪問履歴の一覧・表・地図
- 公共交通の往路・復路と乗換メモ、旅程別の持ち物チェックリスト
- 端末内保存、書き出し

**第2段階: 当日提案を強化**

- 時間帯別の降雨、営業情報、実際の経路と移動時間による提案と再確認
- 公共交通の経路・乗換・時刻の取得と再確認、過去の評価を反映した並び替え、雨天代替案、予算

**第3段階: 端末間利用**

- 自動バックアップ、PC 閲覧、家族での共同編集、写真の同期
- 共有時の同時編集と競合解決、アカウント権限の設計

## 決めたい点

1. 主な出発地と移動手段（例: 大阪から車）。
2. 家族で共有するか、まず本人だけで使うか。
3. これまでの旅行記録を初期登録する際、手入力だけでよいか、写真や位置情報からの取り込みも必要か。

- [Google Maps Platform: Routes API](https://developers.google.com/maps/documentation/routes)

- [Gemini API: API キーの扱い](https://ai.google.dev/gemini-api/docs/api-key)
