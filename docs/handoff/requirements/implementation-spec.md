# APK実装のための整理

## 体験の中心

「思いついた場所を貯める → 今の条件で探す → 旅のしおりを作る → 実際の記録にする → 地図や表で再発見する」。楽しいデザインを保ち、スマートフォンの幅でもすべての操作が押せること。

## 初期版の受入条件

### スポット

- 名前やメモで登録・修正・削除できる。URL共有や音声入力からの追加も目標とする。
- 住所・座標を確認し、曖昧な名称は候補選択を求める。誤った位置へ自動でピンを置かない。
- 登録済みの全スポットを同じ地図に表示し、「すべて／行きたい／行った」で絞る。行きたいかつ訪問済みの地点も一件として扱い、訪問履歴を紐付ける。密集地点はまとめて表示する。
- 一覧からスポットのメモ、過去の訪問、関連旅程を開ける。

### 計画と提案

- 「白浜アドベンチャーワールドに1泊」「雨なので屋内」「午後から」などの日本語入力を受け、保存済み候補と過去の訪問先から提案する。
- 出発地、日時、交通手段、同行者、予算、残り時間の条件を保存・編集できる。
- Geminiによる要約・行程案は編集可能な下書きとして提示する。未確認の営業時間、空室、料金を確定情報として表示しない。
- 行程は日帰り・宿泊の両方を扱い、予定時刻、場所、休憩、代替案、予約メモを編集できる。

### 交通

- 車・公共交通を選べる。
- 公共交通では往路・復路ごとに複数の移動区間と乗換を登録・編集・保存できる。駅・停留所、路線・便、出発・到着時刻、乗換余裕、切符・予約メモを保持する。
- 自動取得する時刻や運賃は取得日時を伴い、手入力メモと区別する。自動乗換検索の接続は第2段階でもよい。

### 持ち物

- 旅程ごとの項目追加・修正・削除、チェック、必要数と担当者の設定を可能にする。
- 天気や同行者に合わせた候補を追加できるが、提案後にユーザーが直せる。定番リストの再利用を検討する。

### 訪問履歴

- 計画から「行った」に変換でき、計画外の外出も直接記録できる。
- 実際の日付、訪問場所、写真、感想、天候、費用、再訪希望を保持する。同じ場所への複数訪問を残す。
- 履歴は一覧・表・地図と検索で見返せる。雨の日や同行者などの絞り込みを想定する。

### 保存と運用

- 最初は端末内に永続保存し、通信が途切れても登録済み情報を閲覧・編集できる。JSON/CSVなどでの書き出しと機種変更用バックアップを用意する。
- Gemini APIキーをソースやAPKに固定しない。個人用試作の設定画面入力と、本格運用時の安全な中継方式を区別する。
- 画面はスマホの表示領域・システムバーを考慮し、下部ナビや保存ボタンが隠れないようにする。

## 参考データモデル

| レコード | 主なフィールド | 関係 |
| --- | --- | --- |
| Spot | ID、名前、住所、緯度経度、地図ID、URL、屋内外、タグ、メモ | PlanStopとVisitから参照 |
| Plan | ID、日付、出発地、同行者、条件、予算、予約メモ | PlanStop、TransportLeg、PackingItemを所有 |
| PlanStop | ID、順序、予定時刻、Spot、所要時間、雨天代替、メモ | Plan内の時系列 |
| TransportLeg | ID、往路/復路、交通手段、出発・到着、路線/便、時刻、乗換余裕、切符メモ | Planに複数紐付く |
| PackingItem | ID、品名、数量、担当、チェック状態 | Planに紐付く |
| Visit | ID、訪問日時、Spot、Plan参照、天候、費用、感想、写真、再訪希望 | 同じSpotに複数件可 |

## 優先順位

1. 端末内のスポット・旅程・訪問・交通・持ち物の永続保存と編集。
2. 全スポット地図、状態別フィルター、履歴の表と検索。
3. Geminiによる下書き、天気と残り時間を使う提案。
4. 現在の営業・経路・乗換情報の取得と再確認。
5. PC表示、家族共有、写真の同期。

この順番は実装の提案です。元の構想メモの段階分けも参照してください。
